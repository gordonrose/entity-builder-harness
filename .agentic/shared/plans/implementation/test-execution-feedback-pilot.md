# Test execution feedback pilot

User approved implementation on 2026-11-07. Worktree and lifecycle remain in the
current session log. No commits, auxiliary worktrees, nightlies or AWS operations.
Preserve the earlier uncommitted migrations and the known image packaging gap.

## Implementation and consumer inventory

- Policy: test-execution standard; testing workflow, completion and diagnostic
  workflows; testing index and selector guide. These explain when, not duplicate
  runtime definitions or change feature acceptance rules.
- Catalog: optional closed feedback metadata, explicit entity-smoke unit and
  bounded DynamoDB/PostgreSQL/server/tooling classifications. Existing commit
  and integration boundaries, stage/effects and protected CI argv stay intact.
- Selector: existing impact/dependency/caching authority; named execution-policy
  helper validates metadata, explains decisions and retains safe observations.
  A development-only path retains all obligations while running eligible local
  leaves. Explicit selection remains requested-check-only. No new registry.
- Feature: public npm check/type/test commands, existing verification-wrapper
  dispatch, current runner and compiler; add type-level contract proof. Review
  ownership binds feature proof separately from app/product composition.
- Consumers: existing commit gate, PR integration workflow, local-main verifier,
  complete selector/cross-language diagnostic fixtures, disposable runner copies
  and semantic cache contracts. No silent bypass or current source hash reset.

## Diagnostic predicate and privacy inventory

| Boundary | Condition and outcome | Owner/proof |
| --- | --- | --- |
| Feedback declaration | missing means unclassified; malformed shape/type/stage rejected | execution_policy.py; selector mechanics and actual catalog cases |
| Development request | only path-scoped local feedback; CI/staged/preparation/aggregate substitutions rejected | selector CLI and plan validation fixtures |
| Required dependency | unavailable fast prerequisite blocks, never silently omitted | existing dependency engine; regression with a blocked child |
| Evidence reuse | matching success reused; source/runtime/contract changes invalidate; failure never reused | existing cache plus focused mechanics cases |
| Run retention | unique owned ignored directory, no symlink/overwrite, safe whitelist; write failure explicit | policy helper and disposable report fixtures |
| Results | focused/development success never establishes integration; actual original outcomes retained | report projection, CI/local-main wiring and negative fixtures |

No product/provider diagnostic schema changes. Tooling uses finite finding codes
and trusted declared logical paths only; raw exceptions/output and configuration
values are excluded. Catalog/runtime identities continue to bind proof. Runtime
source reviews will name exact changed bytes and test owners before final proof.

## Acceptance and verification

1. Focused exploratory tests cover metadata, full-plan feedback/pending results,
   report privacy/isolation, source and runtime invalidation and blocked gates.
2. Actual catalog selection examples cover feature changes, DynamoDB configuration,
   PostgreSQL mapping/migration, server configuration and undeclared dependency.
   Use controlled source checkpoints/fixtures, not the entire accumulated dirty
   ledger as a claim about an ordinary feature edit.
3. Registered entity-smoke check proves current runtime/type cases, failure
   propagation and matching-result reuse. Record duration; estimates are advisory.
4. Consolidated self-review closes the inventory, docs, wrapper consumers and
   source-matched reviews before final frozen registered selector/feature proof.
5. Validate full impact, then execute authorised local integration obligations.
   Keep the known platform-shell-payload failure and dependent blocks visible.
   No local pass establishes container or live AWS readiness.

Results and exact commands belong in the session log. No test files are moved,
no coverage removed for speed, and no cache identity algorithm is replaced.

## Consolidated source review

Implementation, direct callers and tests reviewed before final registered proof.
The existing selector keeps graph discovery, permissions, prerequisite freshness,
private receipts and staged/CI/local-main enforcement. The policy helper owns
only closed metadata and safe historical observations. Development is partial
even when its eligible checks pass. Malformed declarations and unsafe retention
produce bounded findings; neither turns an original failure into success.

Feature commands use the existing app compiler and runner. Type assertions are
included by the no-emit compiler, not falsely counted as runtime discovery.
The literal wrapper propagates failures. Real catalog cases preserve feature,
DynamoDB, PostgreSQL and server obligations; an unsupported future proof remains
a gap. Feedback adoption is intentionally incremental: unclassified owners and
assembled server/product checks remain at their original boundaries.

selection method passed its expanded feature/infrastructure cases; the wrapper's
success/failure dispatch case and app type/runtime commands passed. Two initial
test-expectation errors were corrected (a timing-key substring is not retained

leaf catalog entry). No production behavior was weakened to satisfy these tests.

integration/package/live boundaries will be recorded in the session log.
