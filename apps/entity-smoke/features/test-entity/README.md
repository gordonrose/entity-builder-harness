# Test entity

`test-entity` is a small record feature used to qualify the path from validated
attributes to persistent storage. For example, creating a record generates its
ID and timestamps, checks its attributes, then asks the supplied repository to
insert it. It is handwritten, not generated code or a generic CRUD framework.

| Area | Responsibility |
| --- | --- |
| `contract/` | types, runtime schemas, caller errors and safe validation, stored-row and ID-conflict diagnostics |
| `domain/entity.ts` | attribute normalisation, archive and Core deletion lifecycle transitions |
| `domain/services/` | one named file per create/read/list/update/archive/restore/delete/purge-assessment use case |
| `persistence/` | repository contract, local in-memory test double and provider-neutral relational implementation |
| `transport/http.ts` | private smoke-command adaptation; business rules remain in services |
| `migrations/` | ordered app-owned schema source, consumed by target composition |
| `index.ts` | deliberate exports only; implementation stays in its owning files |

The [service dependencies](domain/services/dependencies.ts) contain `Clock`,
`UuidGenerator`, lifecycle policy and repository
dependencies. System identity and timestamps are generated by those injected
capabilities. `uuidValue` and `occurredAt` are caller-supplied values that are
validated and normalised separately. Nullable values are stored as `null`; an
empty array remains distinct from `null`.

Ordinary reads and the named `status, createdAt` index exclude logically deleted
records. Archive is business visibility only. Core controls logical deletion,
restore-window calculation and purge eligibility; this feature never performs a
hard purge. Archive does not itself hide a record from this repository's ordinary
reads: it changes the separate `visibility` attribute. The in-memory repository
is local-test infrastructure only.

## Relational storage

The relational implementation exists, but it does not select an AWS service,
open a database connection, load credentials or run migrations itself.

| File | What it does |
| --- | --- |
| [repository.ts](persistence/repository.ts) | Defines the feature's get/create/save/status-list operations. Raw get retains deleted facts for restoration; ordinary service get filters them out. |
| [relational/contracts.ts](persistence/relational/contracts.ts) | Defines `TestEntityRelationalExecutor`: target-supplied execution of SQL text plus separately bound values, returning rows or the selected error. |
| [relational/repository.ts](persistence/relational/repository.ts) | Implements `relationalTestEntityRepository(executor)`: INSERT-only creation, UPDATE-only saving and indexed reads. It neither upserts nor retries failures. |
| [relational/mapping.ts](persistence/relational/mapping.ts) | Internally converts entities to parameters and validates returned rows, including bigint text, dates, nullable arrays and lifecycle facts. Invalid rows produce the feature's stored-record diagnostic rather than an unchecked branded entity. |
| [in-memory.ts](persistence/in-memory.ts) | Supplies `inMemoryTestEntityRepository` for local tests; ID collisions cannot overwrite the original and saving cannot recreate a missing record. |

For example, an empty `secondaryCategories` array becomes the bound JSON value
`"[]"`; a null value becomes SQL NULL. Neither is interpolated into SQL text.
PostgreSQL may return the integer attribute as text and timestamps as `Date`
objects. The mapper checks safe integer bounds and normalizes dates before
returning the feature's typed entity. A malformed lifecycle or unsafe integer
returns no entity; diagnostic detail identifies only the rejected field class,
not the row or supplied value.

The [target PostgreSQL composition](../../../../infra/04.deploy/03.product/entrypoints/entity-smoke/postgresql.ts)
selects the actual executor and checked schema binding. The feature exposes its
ordered [migration source](migrations/v0001-test-entity.ts); target administration
owns permissions and the governed migration runner owns executing it. A SQL
declaration or fake executor is not evidence that a real database was migrated.

## Mount and command flow

The public [app index](../../src/index.ts) re-exports this feature and
`createEntitySmokePersistenceApp`, implemented in
[src/persistence/app.mount.ts](../../src/persistence/app.mount.ts). That factory
receives services, a readiness observation function and a close hook. It registers
the feature catalog, the command observation profile, the health contribution
and one POST route at `/entity-smoke/test-entity`.

```text
target supplies clock, UUID generator, policy and database executor
  -> public durable app mount receives assembled services
  -> private HTTP command adapter calls one service
  -> entity rules and repository return a value or selected failure
  -> adapter projects HTTP body and separate internal diagnostic evidence
```

For a command such as `{ "action": "assess-purge", "id": "...",
"retentionSatisfied": true, "legalHold": false }`, the adapter first checks the
ID and boolean attributes. The service reads the record and delegates eligibility
to Core. An active record returns HTTP 200 with
`{ "eligibility": "not-deleted" }`. A missing record returns HTTP 404 with
`{ "error": { "code": "TEST_ENTITY_NOT_FOUND", "message": "The test entity was not found." } }`,
not a successful result containing an error. This example abbreviates the ID;
an actual command requires a valid UUID. No command executes a hard purge.

Returned feature failures keep their stable caller code/message. Their primary
record is internal response observation data; companions go through the optional
request diagnostic callback. They are not HTTP body fields. An absent, throwing
or rejecting callback cannot change the selected response or replay the operation.
Read/list dependency throws remain the original error for the Platform boundary
to handle. The route's public auth declaration does not authorize internet
exposure: deployment keeps this smoke surface private.

## Tests and present limits

From the repository root, run the registered local unit:

```bash
bash scripts/repo/check-selection/script.sh --checks entity-smoke-runtime --execute-local --explain
```

The [schema/service diagnostic cases](../../tests/test-entity/integration/diagnostics-runtime.test.ts),
[relational mapping cases](../../tests/test-entity/integration/relational-repository-runtime.test.ts)
and [mounted-command cases](../../tests/test-entity/integration/mounted-command-runtime.test.ts)
exercise source-discovered local tests. The mount cases use a recording registry
and in-memory dependencies, not a real server/database. The separate
[composition fixture](../../../../scripts/04.deploy/lifecycle/20-build/entity-smoke-composition/runtime-test.mjs)
also exercises an actual local server and its internal diagnostic delivery.
Neither establishes packaged-image, real PostgreSQL or live AWS acceptance.

The [feature boundary](../../../../.agentic/03.product/feature/standards/feature-boundary.md)
and [pilot plan](../../../../.agentic/03.product/feature/plans/implementation/first-persistence-feature-pilot.md)
own creation requirements; the
[isolated deployment plan](../../../../.agentic/04.deploy/plans/implementation/entity-smoke-core-platform.md)
owns the remaining package/target/live proof. Diagnostic-processing faults and
some not-found/visibility errors still have explicit partial-adoption debt in
the existing review ledger. This guide corrects the persistence/mount overview;
it is not a complete export-by-export schema or service walkthrough.
